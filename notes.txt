## why does backend and frontend have their own respective packages and tsconfig?

its a monorepo, one github repo with multiple projects inside of it (backend and frontend)
realise they both dont need the packages each other needs, and also they both compile differently,
so if you put it all in the same pacakages and tsconfig, it will break 

backend :
its a node.js and express server, talks to database, and database sends data back as json
ONLY NEEDS : node.js libraries -> express, postgres, cors 
HOW IT COMPILES : typescript -> into node.js javascript, and it will run on a server 

frontend :
its a react native/ expo app, it runs on a phone, shows UI, and talks to the backend
ONLY NEEDS : react native libraries -> expo, react-native 
HOW IT COMPILES : typescript -> into react native javascript, and it will run a someone's phone

they both still share packages though
THEY BOTH NEED : supabase/supabase.js, backend using the service key, frontend using the anon key 
    

## what does supabase auth do?

it handles the signup, sign in, supabase will given token immediately, token gets sent to your backend with every request
backend will never see a password

## what is a compound response? 
one route giving back multiple pieces of information 

## whats the diff between tsx and ts?
ts means pure typescript and tsx is typescript with jsx ( html like elements )

## why do need a remote control aka createClient() for backend and frontend?
backend -> use service role key, bypasses the RLS, uses verify tokens and does admin opererations, doesnt touch phone 
frontend -> uses anon key, respects RLS, handles login/logout/session on the user's phone.

## package managers !!
they manage your project dependecies -> doing things like installing, updating, and removing packages. 
they basically install packages and run scripts 
eg : npm, yarn (created by facebook), pnpm (newest and most efficient with disk space)

## added render as remote server instead of running backend on laptop, why? 
this is called deployment 
makes the backend reachable from everywhere in the world, wifi, cellular 
url will never change, and laptop wouldnt need to be on for it to work

## how avery made everything load faster YAY for images
frontend stuff ig -> first did svg for best quality, 
but lost texture and whatever in figma, hence I did png x1x2x3 for different devices, 
followed by realising diff between expo images and native expo images,
 then I tried tinier and also learned loading speed between the tunnels and same lan, 
 and then finally asset to preload

 interview telling what i did:
 Chose PNG over SVG for blurred/gradient assets (SVG doesn't preserve Figma blur effects) — matched format to content, not just "best practice" default
Exported @1x/@2x/@3x for device density support
Standardized on expo-image over RN's built-in Image for consistent behavior + built-in caching
Compressed all assets via TinyPNG (lossless for this content type, meaningful file size reduction)
Root-caused perceived slowness to --tunnel dev mode, not asset size — switching to --lan cut load time to near-instant
Added asset preloading + splash screen hold to eliminate pop-in on screen load
